# 2.4.0 UI 改动备忘

四项改动各自的关键实现点与踩坑记录，便于后续维护时不再重复试错。

## 1. 主页 Tab 横向非线性切换

位置：`ui/navigation/KibaMainScreen.kt`（内容区 `AnimatedContent` 的 `transitionSpec`）。

- 只在 **Tab ↔ Tab** 时生效：`initialState as? KibaTab` 与 `targetState as? KibaTab` 都非空。
  进入 / 退出二级页仍走原来的「右侧滑入 / 滑出」。
- 方向由 tab 序号差决定：`direction = if (target.ordinal > initial.ordinal) 1 else -1`。
  `+1` 时旧页向左滑出、新页从右边屏幕外飞入；`-1` 反之。
- 缓动是**非线性**三次贝塞尔 `CubicBezierEasing(0.22f, 0.85f, 0.16f, 1f)`：
  一起步就走、尾段慢慢咬合。入场 380ms、退场 340ms，配合淡入淡出。
- 位移用**整屏宽度**（`full`），不是 `full / 8` 那种轻微位移——用户要求的是「从屏幕外飞入」。
  两页位移互补，任何时刻都正好拼满屏幕，不会露出背景。

## 2. 关于页：动态变色背景 + Logo 特效 + 文字特效

位置：`ui/settings/AboutEffects.kt`（新增）+ `ui/settings/AboutScreen.kt`。
原来的 `ui/common/AboutBgEffect.kt`（AndroidView + RuntimeShader + 120dp blur）
与 `res/raw/about_bg_shader.glsl` 已删除：整页现在共用一个逐帧时钟。

- 时钟 `rememberAboutAnimationTime()`：`withFrameNanos` 累加真实秒数，返回 `State<Float>`，
  **只在 draw 阶段读**——逐帧只失效绘制、不触发重组。这是相比「每帧 setState」最关键的一条。
- 调色板：亮 / 暗各 3 套 × 4 色，12 秒一次交叉过渡（smoothstep `t*t*(3-2t)`），
  序列 `P1→P0→P1→P2→P1`。颜色先做饱和度 ×1.18、亮度 −0.015 的强化。
- 背景 `AboutGradientBackground`：线性底色 + 4 个正弦 / 余弦漂移的径向光斑，
  半径 `0.62 * maxDimension`，速度 `time * 0.12`，四个频率互不整除（0.62~0.9）避免明显循环；
  最后用 `BlendMode.DstIn` 叠一条「上白下透明」的竖向渐变，让下半页自然淡出
  （必须在 `CompositingStrategy.Offscreen` 图层里做，否则会把底下页面一起裁掉）。
- Logo `AboutGradientLogo`：图标 bitmap **只保留 alpha**（像素染白），
  渐变矩形 + `drawImage(blendMode = DstIn)` 把流动渐变灌进 Logo 形状。
  渐变矩形必须只画在图标矩形内，否则 DstIn 之外会留下整片底色。
  辉光是**独立一层**（`BlendMode.Plus`）——放进同一个 Canvas 会被 DstIn 按图标 alpha 切掉。
- 字标 `GradientWordmark`：`drawWithContent` 里先画文字，再 `SrcIn` 灌渐变，
  最后 `SrcAtop` 扫光。**扫光不能用 Plus**：Plus 会画在文字外的透明区域，成一条白带。
  不用 `TextStyle(brush = …)` 是因为那要求每帧重组换 brush。
- 入场动画 `rememberHeroEnter(delay)`：Logo / 字标 / 副标题 / 版本号依次 0/90/160/220ms 淡入上移。

## 3. 顶栏「舞萌 / 中二」切换开关

位置：vendored `top/yukonga/miuix/kmp/basic/BlurTopAppBar.kt` +
`glass/GlassTopAppBar.kt`（两处重载）+ `ui/navigation/TopBar.kt` + `KibaMainScreen.kt`。

- miuix 顶栏新增 `largeTitleTrailing` 插槽，落在大标题**同一行**（`Row` + `Text(weight(1f))`），
  与大标题垂直居中对齐。
- **不要**自己做折叠进度：插槽在大标题自己的 `graphicsLayer` 里，用的是
  `largeTitleAlpha = 1 - collapsedFraction * 3` 与同一段 `translationY`，
  所以消失 / 出现与文字动画严格同频（用户明确要求）。
- 折叠到 1/3 之后 `largeTitle` 已被 `clipToBounds` 裁剪，alpha 也是 0，不会再吃点击。
- `KibaGameSwitch`：总宽 88dp（2 × 44dp）、高 28dp，只留「舞萌」「中二」四字；
  选中滑块 `animateDpAsState + spring(0.82f, 460f)`，主色调 18% 透明度做底。
- 状态从 `SongsScreen` 提到 `KibaMainScreen`（`gameType`），持久化仍走 `SpUtil.setGameType`；
  `SongsScreen` 改为接收 `gameType` 参数，列表首项的原分段开关已删除。
  换游戏时列表 `scrollToItem(0)`，避免停在上一个曲库的中段。

## 4. 设置 → 数据 → 曲库更新：两边一起更

位置：`ui/settings/SettingsScreen.kt`。

- 摘要第一行固定展示两个版本：`舞萌 <版本> · 中二 <版本>`（未同步显示「未同步」）。
- 点击走 `KibaState.refreshAllSongData(context, showProgress = false)`：
  舞萌沿用「有新版才下载」，中二曲库小、直接全量刷新；设置页不点亮曲目页的进度卡，
  进度看本行摘要（检查 / 下载字节数 / 失败原因都在这行）。
- 版本号读取放在 `remember(syncState / chuniSyncState)` 里：SpUtil 的版本值不是
  snapshot state，只在首次组合读一次的话，更新完摘要会停在旧版本号。
